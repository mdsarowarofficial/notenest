the app actually does (`PRIVACY_DATA_INVENTORY.md`, the code, the privacy
policy). Where Google's own wording could be read two ways, the answer says so.
Play's forms change; if a question here does not match what you see, trust the
console and the evidence in the inventory, not this file.

push notifications (switched off), real-time group video, payments.

NoteNest is a study notebook for university students. Your notes live on your phone and work with no internet. A cloud account is optional and only adds sharing, chat and classes.

WRITE AND ORGANISE

YOUR DATA, YOUR CONTROL
• Back up to your own Google Drive and restore on a new phone

Available in English and Bangla, with light and dark themes.

## 6. Data safety form

Basic questions:

| Question | Answer |
|---|---|
| Does your app collect or share any of the required user data types? | **Yes** |
| Is all of the user data collected by your app encrypted in transit? | **Yes** (Firebase over HTTPS) |
| Do you provide a way for users to request that their data is deleted? | **Yes** |
| Delete-account URL | the `#delete-data` URL in section 1 |
| Can users ask for some data to be deleted without deleting the account? | answer as you prefer. Today the honest answer is: no separate control; deleting the account removes the cloud profile, groups, shares and index entries |

**Data types.** For each, "Shared" is **No** for all of these. Reasoning, so
you can judge it yourself: Firebase and Crashlytics are Google acting as your
service provider, which Play's definition of "sharing" excludes, and anything a
student sends to a classmate is a transfer they start themselves, which is also
excluded. If you read the definition more strictly, set Messages to "Shared".

| Category → type | Collected | Required or optional | Purpose |
|---|---|---|---|
| Personal info → **Name** | Yes | Required for a cloud account | App functionality, Account management |
| Personal info → **Email address** | Yes | Required for a cloud account | App functionality, Account management |
| Personal info → **User IDs** (Firebase account ID) | Yes | Required for a cloud account | App functionality, Account management |
| Personal info → **Other info** (university, student/teacher role) | Yes | Optional | App functionality |
| Photos and videos → **Photos** (profile picture, photos sent in chat) | Yes | Optional | App functionality |
| Audio → **Voice or sound recordings** (voice messages in chat) | Yes | Optional | App functionality |
| Messages → **Other in-app messages** (chat, class posts) | Yes | Optional | App functionality |
| Files and docs → **Files and docs** (class files, assignment submissions) | Yes | Optional | App functionality |
| App info and performance → **Crash logs** | Yes | Required (cannot be switched off) | Analytics |
| App info and performance → **Diagnostics** | Yes | Required | Analytics |
| Device or other IDs → **Device or other IDs** (Crashlytics installation ID) | Yes | Required | Analytics |

**Not collected, answer No or leave unticked:** location, contacts, calendar,
financial info, health and fitness, web browsing, search history, installed
apps, SMS or call logs, advertising ID.

Things people ask about and the answer:

* **Notes, subjects, exams, tasks.** They stay in the phone's own database and
  are not sent to you, so they are not "collected". They reach the cloud only
  when a student shares one, and then they count under Messages / Files.
* **Google Drive backup.** The file goes to the student's own Drive, never to
  you. Not collected.
* **Dictation.** The phone's own speech recogniser handles the audio (usually
  Google's). NoteNest never receives it. Not collected.
* **Encrypted at rest on the device:** the app does not encrypt its own
  database. The question is about data you collect, which is held by Firebase
  (encrypted at rest by Google).

## 7. Content rating questionnaire (IARC)

Start the questionnaire from Policy → App content → Content rating. Pick the
category **Reference, News or Educational**. Then:

| Question | Answer |
|---|---|
| Violence (any kind) | No |
| Sexual content or nudity | No |
| Profanity or crude humour | No |
| Controlled substances (drugs, alcohol, tobacco) | No |
| Gambling or simulated gambling | No |
| Does the app let users interact or exchange content? | **Yes** (chat, class posts, shared notes) |
| Does it share the user's location with others? | No |
| Does it allow users to purchase digital goods? | No |
| Does it contain unrestricted internet access or web browsing? | No (the app opens a Drive link in the browser only for class files) |

Because students can message each other, expect a rating that carries a
"Users interact" note. That is correct and expected; do not try to answer your
way around it. The in-app report and block, and `docs/MODERATION.md`, are the
evidence that you handle it.

## 8. App access (for the Play reviewer)

The reviewer cannot see classes, chat or sharing without an account. Create two
ordinary accounts in the app first (one student, one teacher), confirm the email
on each, then paste this, with real values:

```
NoteNest works fully without an account (notes, exams, planner, cover pages,
convert). Classes, chat and sharing need a cloud account.

Test account 1 (student): <email>  /  <password>
Test account 2 (teacher): <email>  /  <password>

How to sign in: open the app, enter the email and password under "Sign in".
Then People → Classes / Chats / Groups.

Sign in with Google is also offered; the accounts above use email and password
so no Google login is needed.
```

Keep the two accounts and their passwords unchanged for as long as the app is
under review.

## 9. Release

1. Create a release under **Internal testing** first. Upload
   `build/app/outputs/bundle/release/app-release.aab` (version 1.0.2, build 5).
2. Accept Play App Signing when asked (it is the default for new apps).
3. After the upload, copy the **App signing key certificate SHA-1** from
   *Test and release → App integrity* into Firebase (*Project settings →
   Your apps → Add fingerprint*), download the new `google-services.json`, and
   have it rebuilt. Without this, Google sign-in does not work in the version
   Play installs.
4. If the developer account is a personal one created recently, Play will ask
   for a closed test with a minimum number of testers over a minimum number of
   days before production. Read the exact numbers on the console dashboard; they
   change.
